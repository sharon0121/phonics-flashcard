## 2026-08-27 三款遊戲單字測驗：修正英文題目/中文答案被提前切斷的問題

Sharon 反映玩單字測驗時「英文題目跟答案有時候沒念完就跳下一題」。查出兩個根因，三款遊戲（Puyo/Tetris/Block Puzzle）都用同樣模式改：

- **根因 1（主因）**：每次「出新題目要唸英文單字」的 `speak()` 函式，內部都會先呼叫 `window.speechSynthesis.cancel()` 才開始唸。但「答對/答錯後唸出正確答案中文」跟「進入下一題唸英文單字」中間只隔一個寫死的 `setTimeout(...,1100)`，如果中文答案唸得比較久（字數多、語速慢），常常還沒唸完，下一題的 `speak()` 就已經觸發、把還在播的中文語音整個切斷。同理英文題目本身也可能被「答題後緊接著要唸中文答案」的流程間接波及。
- **根因 2**：`setTimeout` 固定延遲是用「猜」的方式估計語音要唸多久，跟實際字數/語速完全脫鉤，本質上就是不可靠的做法。
- **修法**：把 `speak(text, rate)`／`speakZh(text)` 兩個 fire-and-forget 函式，合併改寫成一個會回傳 Promise 的 `speakAsync(text, lang, rate): Promise<void>`，靠 `SpeechSynthesisUtterance.onend`/`onerror` 真正等到瀏覽器唸完才 resolve。**刻意拿掉逐字呼叫時的 `cancel()`**（Web Speech API 本身在語音播放中呼叫 `speak()` 就是自動排隊接續播放、不會打斷正在播的內容，靠這個天生行為讓「英文題目唸完→（等玩家作答）→中文答案唸完→下一題英文」自然接續不重疊），改成只在 `triggerQuiz()`（真正的情境切換：從遊戲畫面切進測驗）呼叫一次 `cancel()` 清掉可能殘留的遊戲內語音。原本寫死 1100ms 的「答題後多久跳下一題」計時器，改成真正 `await speakAsync(zh讀音)` 等語音實際播完＋350ms 前置停頓＋300ms 播完後緩衝，才觸發下一題/恢復遊戲的 state transition。
- **踩坑（自己新增的 code 有一個真實的健壯性漏洞，是這次順便補上的）**：一開始只加了 `onend`/`onerror` 就直接把 promise 包起來，用 Playwright 假造一個會丟例外的假 `speechSynthesis.speak()` 測試時，發現如果 `speak()` 呼叫本身同步丟例外（某些瀏覽器對不支援的語言/語音會這樣），`onend`/`onerror` 都不會觸發，這個 Promise 會**永遠不 resolve**，等於整個測驗卡死在該題、小朋友永遠不能繼續玩。修法：`speak()` 呼叫包 `try/catch`＋額外加一個 8 秒的保底 `setTimeout`（`finish()` 用 `settled` 旗標防止重複 resolve），確保無論瀏覽器語音合成出什麼狀況，測驗最多卡 8 秒就會自動放行，不會真的把遊戲卡死。

## 重要教訓

- **改東西前務必先確認元件真的有被路由使用**：憤怒牛曾經有 `EnglishMode.tsx`/`MathMode.tsx` 兩個完全沒被 import 的殘留檔案（真正在跑的是合併版 `AngryCowView.tsx`），我一開始改錯檔案，改了老半天手機版排版問題完全沒生效在正式站上，後來才發現並刪除死碼。
- 小精靈大探險先前「手機無法讀取」的問題，一開始懷疑是網址含 "vault" 被資安 App 攔截，後來排除；真正原因是 `wordVaultSettings.ts` 的 `useLearnedMazeWords` 每次 render 都回傳新陣列，違反 `useSyncExternalStore` 的快取契約，造成無限重渲染在效能較弱的手機上直接當機——**任何 `useSyncExternalStore` 的 getSnapshot 函式都必須在資料沒變時回傳同一個陣列參考**，這是這個 codebase 反覆出現的地雷。
- **多個 `<span>` 文字片段組成一句話時，外層容器不能用 `flex`**：豬探長遊戲把線索句子拆成一個個 `<span>`（用來標記可點的單字）直接放進 `className="flex items-center justify-center"` 的容器裡，結果瀏覽器把每個 `<span>` 當成獨立 flex item，字與字之間的空白全被吃掉、整句黏成一長串溢出邊界。修法：`flex` 只放在外層置中容器，裡面包一層普通 `<span>`/`<p>` 讓文字片段用正常inline排列，才會正常換行、保留空格。
- **`useState` 的 lazy initializer 裡不能讀 `ref.current`**：新版 eslint-plugin-react-hooks 的 `react-hooks/refs` 規則會擋下「render 期間讀取 ref」，包括寫在 `useState(() => ...)` 初始化函式裡面。要在 mount 時就用到 ref 的初始值，改成先算出初始資料（不碰 ref），再用該資料建立 `useRef(初始值)`（ref 的建構運算式本身不算「render 期間讀取」）。
- **同一元素上「用 CSS class 做動畫的 transform」跟「inline style 做定位的 transform」會互相打架**：怪獸點心店裡，點心用 `style={{transform:'translate(-50%,-50%)'}}` 置中在座標點，同一個 `<span>` 又套用 `cell-pop`（class 動畫，keyframe 也設 `transform:scale(...)`）——動畫播放期間會整個蓋掉 inline 的置中 transform，播完瞬間「彈回」正確位置，看起來像頓格/跳動。修法：把「定位用的 transform」跟「動畫用的 transform」拆到兩層巢狀元素，各自獨立不衝突。同理，共用既有的動畫 class（如 `tier-up-pop`）前務必檢查它是否內建了特定的定位假設（`tier-up-pop` 內建 `translate(-50%,-50%)`，是設計給 `position:absolute;top:50%;left:50%` 用的寫法，直接套在 flexbox 置中的容器裡會把元素往左上角推歪）。
- **flex-wrap 容器用 `justify-center` 時，動態新增項目會讓已存在的項目全部跟著位移**：出餐桌隨複製盤子動作逐漸變多盤，若外層用 `justify-center`，每加一盤全排都會重新置中、舊盤子跟著橫向跳動。改成 `justify-start`（新項目只會加在最後面，不會擠動前面）。同理，外層若用 `justify-center` 做「垂直置中整個內容區塊」，內容長高時也會讓整塊（含所有已放置的座標定位子元素）垂直跳動，一樣要改用 `justify-start`（+ padding-top 模擬置中）才不會有這類「內容變多、既有內容跟著位移」的通病。
- **這個環境裡 Playwright 的 `browser_resize`／`setViewportSize` 會把寬高「打對折再乘2」，跟 `window.innerWidth` 實際不一致**：例如要求 390px 寬，`window.innerWidth` 卻回報 780px；要驗證某個 CSS 響應式寬度（例如手機 390px），要求的數值要先除以 2（實測請求 195 才會得到 390 的實際寬度）。每次要測特定裝置寬度前，先用 `page.evaluate(()=>window.innerWidth)` 校驗實際生效寬度，別直接相信請求的數字。
- **`useState` 更新後想在「本次呼叫」內同步用新值做判斷（例如扣血後立刻決定要不要 Game Over），不能靠讀取 state 變數**（React state 更新是非同步、下個 render 才生效）。做法是額外開一個 `useRef` 鏡射該 state（`useEffect` 同步），在需要「立刻讀到新值」的函式裡手動算出新值、同時寫入 ref 跟呼叫 `setState`，用這個手算的新值做判斷，不要指望呼叫 `setState` 後同函式內讀到新值。
