**絕不在本機有未 commit 修改時執行 `npx vercel --prod --yes`。**

**Why:** 2026-06-01 Sharon 反映，`npx vercel --prod --yes` 把本機 5/28 未提交的甘特圖修改一起部署到線上，導致生產環境被破壞，且原本已部署的版本程式碼沒有提前備份，造成無法完整還原。

**How to apply:**

部署前必須做的事（缺一不可）：
1. 先用 `git tag` 標記目前的線上版本（例：`git tag v1.x-備份`）
2. 只用 selective `git add [只加要部署的檔案]` → `git commit` → `git push`
3. **禁止**在有 "Changes not staged for commit" 的狀態下執行 `npx vercel --prod`
4. 如果非要用 Vercel CLI，先確認 `git status` 完全乾淨

## ⚠️ 2026-06-11 追加：GitHub 自動部署已損壞

`git push` 不再觸發 Vercel 自動部署，必須手動執行 CLI。

**目前安全部署流程（缺一不可）：**
```
git status                    # 確認乾淨，無未提交修改
git add [指定檔案]
git commit -m "..."
git tag vX.X.X
git push && git push --tags
npx vercel --prod             # ← 這步驟不可省略
```

- 所有部署都由 Claude Code 代為執行 `npx vercel --prod`，Sharon 不需要自己跑
- git push 只是備份到 GitHub，不會觸發上線

## ⚠️ 2026-08-14 追加：`vercel --prod` 回報 "Not authorized" 時，加 `--scope tsa-product-mgmt`

Sharon 的專案都在 Vercel 團隊 `tsa-product-mgmt` 底下（product-mgmt-platform、phonics-flashcard、tsa-line-assistant、ad-review-platform、tsa-product-mgmt-platform）。`vercel whoami` 顯示已登入帳號 `sharon-8435`，但直接 `npx vercel --prod` 仍可能回報 `{"status":"error","reason":"deploy_failed","message":"Not authorized"}`（CLI 預設 scope 沒對到專案所在的團隊）。遇到這個錯誤時改用 `npx vercel --prod --scope tsa-product-mgmt` 即可成功部署，不需要重新登入。之後在這些專案部署前，若第一次失敗出現 Not authorized，直接加這個 flag 重試，不用花時間排查登入問題。
