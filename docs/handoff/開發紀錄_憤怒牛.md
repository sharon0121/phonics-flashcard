`/games/angry-cow`（英文版＋數學版＋混合版）目前 v2.4.0。核心檔案：`src/app/games/angry-cow/SlingshotGame.tsx`（three.js+cannon-es 主遊戲邏輯）＋`AngryCowView.tsx`（**唯一**的外層包裝，三種模式合一，`page.tsx` 只 route 到這支）。**注意**：曾經存在的 `EnglishMode.tsx`/`MathMode.tsx` 是舊版遺留的死碼（完全沒被 import），2026-08-04 已確認並刪除——改東西前務必先確認元件真的有被路由用到，不要對著死碼改半天。

**2026-08-04 新增功能**：連續答對 5 次投擲物變長刺球、10 次變斧頭（`createProjectileVisual(tier)`），答錯或超時歸零；每輪 12 秒倒數（`ROUND_TIME_MS`），逾時扣血算失敗；命中畫面加了震動+爆炸音效+光環特效。數學設定改成跟時空戰術隊一樣的「多選難度隊列」（見 [[project-phonics-flashcard]] 的設定統一慣例）。手機版曾經因為 3 隻牛左右間距用固定 30/50/70% 導致窄螢幕答案框重疊，已拉開到 18/50/82%。

**玩法**：3 個跑道（X 位置每輪隨機、不固定 3 槽），每個動物站在木箱上、有自己的隨機距離（500-1000 公尺，對應世界 Z 軸 3-18）。玩家按住動物本體或牠腳下的木箱蓄力，力量表自動來回振盪（三角波，`currentPowerValue()`），鬆手瞬間的力量值要對到該跑道分配到的距離（±50 公尺容忍值）才算命中；命中又分「打對」（答案正確，加分）跟「打錯」（扣一顆心）。距離沒對準只是打偏，不扣血、同一輪可以再試。

**素材管線（給之後處理 Sharon 提供的 PNG 用）**：
- Sharon 習慣把素材放 Google Drive 資料夾分享連結，用 `mcp__claude_ai_Google_Drive__search_files`（`parentId = '...'`）列出資料夾內容，再用 `download_file_content` 抓 base64——檔案通常幾 MB，會超過 token 上限存成 `tool-results/*.txt`，要用 Python script 讀 JSON 的 `content` 欄位 base64-decode 存成真正的 .png（不要用 Read 工具硬讀那個 txt，會超大）。
- 去背/裁切都用本機 Python + Pillow + numpy/scipy（環境本身沒裝，要先 `pip install`）。去背邏輯：取四角當背景色，算每個 pixel 到背景色的歐幾里得距離，用 threshold 判斷前景/背景。**教訓**：如果背景色判斷用「平滑漸層 alpha」，雲朵這種有凹陷（兩個圓弧交界處）的形狀會露出縫隙讓背景色透出來，肉眼看起來像「雲朵有藍色」——這不是色彩問題，是形狀有洞，要用 `scipy.ndimage.binary_closing` 做「先膨脹再侵蝕」把洞填平,同時把 alpha 改成非漸層的 binary（0 或 255），色彩再另外做「去彩度＋往白色拉」的灰階轉換,兩者要分開處理（形狀 mask 跟顏色 shading 解耦）。
- 多幀動作圖（例如長頸鹿 5 個姿勢、木箱 10 個角度+爆炸）用 `scipy.ndimage.label` 做連通元件分析自動切出每一幀的 bounding box，比手動猜座標準。
- **2026-08-04 更正**：`animal-idle.png`／`animal-fallen.png`／`crate-destroyed.png`／`shoot-bar.png`／`cloud-1/2/3.png` 這批舊 sprite 素材檔案還留在 `public/games/angry-cow/`，但遊戲已改用程序生成的 3D mesh+canvas 貼圖，這些檔案目前**沒有被程式碼引用**（orphaned，不是 bug，只是沒清掉）。目前實際會用到的素材只剩 `bg.png`（背景）、`cloud-a.webp`/`cloud-b.jpg`/`clouds.png`（雲朵，用 flood-fill 去背)、`crate-idle.png`/`crate-sheet.png`（木箱貼圖來源，經 canvas 加工）。

**3D 場景關鍵設計**（2026-08-04 更正：此節先前誤植為 Sprite billboard，實際已改為真 3D mesh，見下）：
- 動物（長頸鹿）是 `createGiraffe3D()` 程序生成的 `THREE.Group`（多個 BoxGeometry/CylinderGeometry/SphereGeometry 組成的低多邊形模型，非貼圖），木箱是 `BoxGeometry` 的 `THREE.Mesh`（材質用 canvas 程序產生的木紋貼圖，`createCrateBoxTexture()`，不是外部 PNG）。命中時的「倒下/爆開」效果是 cannon-es 物理引擎把對應的 body 往上/往前推一下產生真實旋轉+位移（`crateBody`/`targetBody` 加入 world 並給 velocity/angularVelocity），純視覺效果，不影響命中判定（命中判定是純數學比對距離，跟物理引擎完全無關）。投擲物（球/長刺球/斧頭）也是同樣模式，`createProjectileVisual(tier)` 用基本幾何體組合而成。
- 相機刻意往下傾斜（`camera.lookAt` 的 Y 給負值）讓草地佔比大於天空,配合 Sharon 提供的參考圖比例（約 30% 天空/70% 草地）。
- 雲朵飄動：6 條固定「高度車道」，同車道內的雲共用幾乎相同的動畫速度＋均勻分散的起始相位（同車道 N 朶雲平均分配整個循環週期,只加 20% 以內的 jitter），這樣才能保證雲朵之間的重疊率長期穩定控制在 20% 以內——如果單純用「隨機速度+隨機起始位置」，快的雲遲早會追上慢的雲導致完全重疊，只是時間早晚的問題。
- **已知的測試環境陷阱**：Playwright headless 分頁的 `requestAnimationFrame` 會被大幅節流（觀察到 2 秒內只跑 3 次 tick，正常應該 120 次），導致「剛按下放開就檢查命中結果」的自動化測試會撞到假的中間狀態（例如物理 body 還沒被加進 world）。不是遊戲的 bug，是測試環境的限制,遇到這種情況要用 `page.waitForFunction` 等真正的狀態轉變而不是猜時間。
